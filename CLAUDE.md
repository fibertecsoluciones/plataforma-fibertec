# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

FiberTec ISP — internal operations panel for a small wireless ISP: clients, payments
(with a "semáforo" / traffic-light status and multi-month exception payments),
field module (solicitudes/leads, actividades/tasks, instalaciones), inventory, and
finances (income derived from payments vs. manually-entered expenses).

The codebase and all UI/domain language is **Spanish** — match it (variables,
comments, commit messages, user-facing strings).

## Commands

All commands run from `backend/` (there is no root package.json):

```bash
npm install
npm run dev            # nodemon, http://localhost:4000
npm start              # plain node, used by Railway

npm run db:init        # runs db/schema.sql against DATABASE_URL — full schema, destructive-ish (CREATE TABLE, no IF NOT EXISTS)
npm run db:seed-admin  # creates the initial admin user from ADMIN_USER / ADMIN_PASSWORD env vars
npm run db:migrate migrations/019_tipo_actividad.sql   # runs ONE migration file (path relative to db/)
```

Requires a local PostgreSQL and a `backend/.env` (copy from `backend/.env.example`).
There is no test suite, linter, or build step.

### Database migrations

`db/schema.sql` is the **current** full schema — kept up to date, so a fresh
`db:init` already includes every migration. `db/migrations/NNN_*.sql` files exist
only to upgrade **already-deployed** databases and are applied one at a time and
manually via `db:migrate` (there is no migration tracking table). When you add a
schema change: update `schema.sql` **and** add a new numbered migration file.

## Architecture

**Stack:** Node + Express (CommonJS) · PostgreSQL (`pg` Pool, raw SQL — no ORM) ·
vanilla HTML/CSS/JS frontend (no framework, no bundler). Deployed as a **single**
Railway service: Express serves `/api/*` and also serves `backend/frontend/` as
static files with an SPA-style fallback to `index.html` (see `server.js`).

Note: `README.md` shows `frontend/` at repo root; it actually lives at
`backend/frontend/`.

**Request flow:** `routes/*.routes.js` → `controllers/*.controller.js` → `config/db.js`.
Each route file does `router.use(requireAuth)` then guards individual routes with
`requireRole('admin')`. Controllers hold all SQL inline and talk to `db.query()`
directly; use `db.pool.connect()` + `BEGIN/COMMIT/ROLLBACK` for multi-statement
writes (see `pagos.controller.js` `registrarPago`).

**Auth:** JWT in `Authorization: Bearer` header, verified in `middleware/auth.js`,
payload `{ id, usuario, nombre, rol }` on `req.usuario`. Two roles: `admin` and
`tecnico`. Frontend stores token + user in `localStorage` (`ft_token`, `ft_usuario`);
`js/api.js` attaches the header and force-logs-out on any 401. Page-level gating is
`protegerPagina(['admin'])` in `api.js`; nav visibility is `soloAdmin` flags in
`js/layout.js`.

**File uploads:** `middleware/upload.js` (multer, evidence photos / receipts →
`backend/uploads/evidencias/`, served at `/uploads`) and `middleware/uploadExcel.js`
(client bulk import via `xlsx`). Uploaded files are gitignored and **not persistent
on Railway** — treat as ephemeral.

**Frontend convention:** every internal page = `X.html` + `js/X.js`, plus shared
`config.js` (sets `window.API_BASE_URL`, `''` when same-origin), `api.js`, and
`layout.js` (`renderLayout(activeId, title)` builds sidebar/topbar + the adeudo
notification bell). Maps use **Leaflet** with Esri satellite tiles — no API key,
no Google Maps.

## Domain logic that lives in the database

Much of the business logic is in PostgreSQL functions/triggers/views in
`schema.sql`, not JS. Key pieces:

- **`vw_estado_pago`** — the payment traffic light. Per client, for the *current
  month only*: `semaforo` ∈ verde/amarillo/naranja/rojo, plus `meses_adeudados`
  and `saldo_pendiente` which DO span all months since `fecha_inicio_conteo`.
  Frontend reads this via `GET /api/clientes`.
- **`fn_fecha_vencimiento(dia, periodo)`** — clamps the pay-day to the month's real
  last day (day 31 in February → 28/29). Any date math about due dates must use
  this rule; `pagos.controller.js` `desgloseCliente` reimplements it in JS.
- **`fn_meses_adeudados` / `fn_saldo_pendiente_automatico`** — compare the *sum* of
  `pagos.monto` per month against `planes.precio` (partial payments don't clear a
  month). Suspended clients freeze the count at `fecha_suspension`.
- **Payments:** one `pagos` row per month per abono; multiple rows per month = partial
  payments. A multi-month "excepción" payment (`meses_cubiertos` 2–3) splits the
  amount into one row per `periodo`, all sharing `grupo_pago`, `es_excepcion = true`.
- **Cliente-ID / folio** (`POP-001`) is generated by the `trg_clientes_cliente_id`
  BEFORE INSERT trigger from the zone `codigo` — never set it in app code.
- **Inventory stock** (`inventario_items.stock_actual`) is maintained only by the
  `trg_inventario_movimiento` trigger on `inventario_movimientos` — never write it
  directly.
- **Actividad status** auto-recalculates (pendiente/en_proceso/completada) from its
  `actividad_puntos` checklist via `trg_recalcular_estado_actividad`.
- **Income in Finanzas** is derived by summing `pagos` (+ `ingresos_extra` for
  one-off charges like installation); only `egresos` are entered by hand.

## Timezone gotcha

Postgres `DATE` columns arrive as `"2026-09-07T00:00:00.000Z"`. Passing that to
`new Date()` shifts the day backward in MX (UTC-6). Use `fechaLocalDesdeTexto` /
`fechaCorta` from `layout.js` for calendar dates; `fechaHoraCorta` (normal TZ
conversion) only for real timestamps where the clock time matters.
